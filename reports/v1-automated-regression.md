## 4. Test runner architecture

`evaluation/runner/src`: `scenarios.ts` (load/validate), `browser.ts` (browser start and CDP attach), `previewUi.ts` (all Preview DOM interaction), `completion.ts` (pure completion logic), `runner.ts` (orchestration, retries, resume, isolation), `results.ts` / `baseline.ts` (files and read-only reference scores), `report.ts` (this report), `cli.ts` (commands). Unit tests: `evaluation/runner/test`.

## 5. Authentication and session strategy

Agentplace login uses Google SSO, which can reject automation-launched browsers. The runner therefore does not log in itself: `npm run browser` starts an ordinary Chrome with a dedicated profile under `.auth/` (git-ignored) and a local debugging port; the user signs in once, and the runner attaches over CDP and reuses that session. No cookies, tokens, passwords or profile data are written to the results or committed.

## 6. How fresh-conversation isolation works

Each attempt opens a new browser tab, and the Preview creates a new agent session for it (`sessionStorage.agentplace_session_id`, also sent as `agent_session_id` on the WebSocket). The runner checks that the history starts with only the welcome page, that the session id has not been used by another attempt in the run, and that it stays unchanged between the two turns. Session ids are stored only as 12-character SHA-256 prefixes. `validate` re-checks that no two successful scenarios share a session.

## 7. Response capture method

The runner types the exact scenario text, verifies the input field content, presses Enter, and waits without fixed sleeps until: the new user turn appears in the history rail, the composer reports `data-pending="false"`, no `aria-busy="true"` region remains, and the visible response (`[data-stage-page] .stage-canvas-page`) is new and unchanged for 2 s. Because the Preview shows only the latest response, earlier replies cannot be mixed in. The visible text and all hyperlinks (text and URL) are stored verbatim. Warnings flag very short or unterminated text.

## 11. Errors, limitations and unresolved issues

- Browser locale: the Preview forwards the browser language to the agent. A first proof-of-concept run with the browser default `hu-HU` returned Hungarian answers to the English prompts (run `candidate-v1-poc-T001`); the runner now pins `en-US`, which produced English answers consistent with the manual baseline. The manual baseline's locale was not recorded, so this remains a possible confounder.
- This report covers one run per case. Two further repetitions and a critical second-pass review of these 20 transcripts were done later and are reported in `final-evaluation-2026-11-06.md`; all judgments remain AI-assisted unless marked HUMAN.
- Selectors (`.stage-composer[data-pending]`, `data-rail-turn`, `.stage-canvas-page`) were verified on 2026-11-06 and may change when Agentplace updates its UI. They are isolated in `previewUi.ts`.
- Headless mode (`npm run browser -- --headless`) exists but was not exercised.
- The Preview agent was not pinned; results apply to whatever state it was in on the run date.
